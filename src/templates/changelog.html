What's new

You're running {{ app_version }}. The list below is everything that changed since the previous release, in plain English.

Hardening round

No behavior changes for most users — this is the security pass.

  • The bundled install update is now signed: the app refuses a release whose checksum file isn't signed with the maintainer key.
  • Every destructive action (clear history, factory reset, prune, vacuum, update yt-dlp, …) now requires you to type a confirmation phrase. Same-origin XHR from a browser extension can't silently trigger them.
  • The per-IP rate limit on heavy endpoints (playable proxy, uploads, helper installs) keeps a runaway tab from flooding ffmpeg.
  • URLs are re-validated after redirects so a paste that points at https://attacker/redirect → http://10.0.0.5/… is rejected before yt-dlp runs.
  • The output-path setting rejects path-traversal tricks, embedded NUL bytes, and symlinks pointing outside the writable tree.
  • The session secret is persisted to a 0o600 file in the data directory; if it can't be written you see a warning banner instead of a silently-rotating key.
  • HSTS only appears on HTTPS requests, never on the localhost HTTP used by the desktop launcher.
  • The release-prelude endpoint can no longer silently fall back to an unverified checksum when the bundled pubkey is missing.
  • SECURITY.md is now in the repository with a private disclosure channel.

Listening & library

  • New radio mode: when the queue runs out, the player picks the next similar track (same artist, then same album, then same folder, then least-played).
  • The Preferences page now has a typed-phrase modal for the most dangerous operations.
  • Storage quota and old-failure age are now user-configurable; the hourly janitor trims oldest-played tracks to stay under the cap.

Diagnostics

  • The Settings › Helpers page now has a one-click Report issue button that opens GitHub with a prefilled bug template including your diagnostics JSON.
  • The rotated log file scrubs bearer tokens, API keys, user:pass credentials, and tracker query strings before writing to disk.
  • Settings writes are now optimistically-concurrent: a second tab editing the same form gets a banner asking it to reload instead of clobbering.

Older changes are in git history. Security issues? Follow SECURITY.md for the private disclosure channel.
